# REduQuest

Русскоязычная desktop-платформа практического обучения профессиям в IT и работе с данными. Иерархия обучения: **профессия → маршрут → комната → миссия**. Data Scientist — первый наполненный маршрут, но не граница платформы.

## Что реализовано

- персональный DS-маршрут из 8 тематических комнат;
- каталог профессий: Data Scientist, Аналитик данных, ML-инженер, Инженер данных и AI-инженер;
- карта каждой профессии из пяти связанных этапов с учебными блоками и стеком инструментов;
- учебный каталог из 224 курсов: 18 полностью авторских, остальные явно помечены как требующие ревью, переработки или наполнения;
- состояния прогресса, доступности и блокировки;
- подробный экран комнаты со списком уроков;
- выбор доступной миссии и карточка следующего шага;
- адаптивная тёмная IDE-компоновка.

## Установка одной командой

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/setup.ps1
```

Установщик проверяет окружение (Node.js 20+, npm, git, свободное место), ставит зависимости,
прогоняет проверки контента и учебного графа, собирает веб- и desktop-версию, создаёт ярлыки
и настраивает автообновление. Ключи: `-SkipChecks`, `-NoShortcuts`, `-NoAutoUpdate`.

## Обновление

```powershell
npm run update
```

Скрипт подтягивает изменения из [репозитория](https://github.com/forit-tech/REQuest-EducationPlatform),
переустанавливает зависимости, если изменился `package-lock.json`, пересобирает приложение
и перезапускает его. `npm run update:check` только проверяет, есть ли новые коммиты.

### Автообновление

Установленная desktop-версия проверяет последний GitHub Release через несколько секунд после
запуска и затем раз в шесть часов. Если опубликована версия новее установленной, приложение
скачивает официальный NSIS-инсталлятор в каталог профиля пользователя и запускает его после
закрытия REduQuest. По клику на уведомление обновление можно установить сразу.

Git-клон для разработки продолжает обновляться через `scripts/update.ps1`. Для выпуска новой
desktop-версии нужно изменить `version` одновременно в `package.json` и `package-lock.json`,
создать тег `v<version>` и отправить тег в GitHub. Workflow отклонит релиз, если тег и версия
не совпадают.

Настройка автоматической установки хранится в `update-settings.json` рядом с профилем
пользователя. Ручная проверка доступна в меню «REduQuest → Проверить обновления».

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\install-shortcuts.ps1
```

## Аудит курса

Курс проверяется четырьмя аудиторами за один прогон:

```bash
npm run audit:course
```

| Аудитор | Что сторожит |
| --- | --- |
| Персонажи | род в речи о себе и о других, обращение к игроку, отказ кастинга вместо тихой подмены, размер состава профессии, палитра эмоций |
| Изображения | разрешение спрайта против размера вывода, полнота набора поз по контракту эмоций, объявленные замены, фоны мест |
| Педагогика | порядок выдачи знаний, конструкция раньше своего урока, разбор, который ничего не объясняет |
| Сюжет | место действия против текста, память о прошлой главе, достижимость концовок, объём сцены |

Политика воротная: критические правила (сломанная сцена, неизвестный говорящий, недостижимая
концовка, необъяснённая конструкция) держатся на нуле всегда, остальные ошибки не должны расти
выше базовой линии в `knowledge/reports/course-audit-baseline.json`. Отчёт с адресами находок
собирается в `knowledge/reports/course-audit.md`.

```bash
npm run audit:course -- --auditor=story      # один аудитор
npm run audit:course -- --course=numpy       # один курс
npm run audit:course -- --full               # все находки, а не первые три
npm run audit:course:baseline                # зафиксировать долг после исправлений
npm run audit:course:test                    # проверки самих аудиторов
```

Размер фигуры внутри холста считает отдельный разбор альфа-канала — `npm run sprites:check`;
его результат аудит подхватывает из `knowledge/reports/sprite-metrics.json`.

### Сюжетные дела

Дело пишется один раз, а играется в нескольких профессиях: героя, место и команду подставляет
маршрут. Поэтому в тексте дела нельзя называть место действия, обращаться к игроку в роде и
начинать главу со знакомства — она может оказаться и второй, и седьмой.

Что аудит считает настоящей историей:

- завязка на `caseStart`, сцены вокруг миссий, отклик после сделанной работы;
- в акте больше одной реплики, в деле — от 350 слов;
- выбор игрока выставляет флаг, который читает либо концовка, либо акт-последствие
  (`requiresFlags`) — сцена, которая приходит только к тому, кто пошёл коротким путём;
- состав дела подобран так, чтобы в каждом маршруте героям хватило разных исполнителей:
  `A1.recast-collision` ловит случай, когда двое авторских героев выходят одним человеком;
- реплики не повторяются дословно в других делах: `A4.template-story` ловит заготовку с
  подставленной темой. Это правило нельзя закрыть, дописав строк, — только настоящим текстом.

Переписанные дела идут парами: главы стоят рядом во всех маршрутах, где встречаются, и вторая
опирается на первую.

| Пара | Главы | Маршруты |
| --- | --- | --- |
| [yaml-basics](knowledge/story/cases/yaml-basics.json) → [linux-network-ops](knowledge/story/cases/linux-network-ops.json) | 2 → 3 | devops, sre, cybersecurity, pentester, soc |
| [relational-databases](knowledge/story/cases/relational-databases.json) → [postgresql](knowledge/story/cases/postgresql.json) | 5–6 → 6–7 | data-engineer, java, python-backend, go, devops |
| [javascript-core](knowledge/story/cases/javascript-core.json) → [web-platform-foundations](knowledge/story/cases/web-platform-foundations.json) | 2 → 3 | frontend, react, pentester |
| [statistics](knowledge/story/cases/statistics.json) → [ml-baseline](knowledge/story/cases/ml-baseline.json) | 6–13 → 7–15 | data-scientist, data-analyst, ml, ai |

Дела, которые играет один маршрут, пишутся как арка профессии: состав дела равен постоянной
команде, поэтому замен, отказов и склеек в них нет по построению.

| Арка | Главы |
| --- | --- |
| java-developer · сервис сверки | java-core → java-core-jvm → spring-services → java-production |
| go-developer · диспетчерская рейсов | go-core → go-core-concurrency → go-network-services → go-production |
| react-developer · диспетчерский интерфейс | react-core → react-architecture → react-production |
| python-backend · сервис доставки | python-web-api → python-databases-async → python-service-production |

### Контракт эмоций

Набор эмоций объявлен один раз в [src/story/emotions.ts](src/story/emotions.ts): у каждой
есть русское название, статус и — для ненарисованных — явная замена.

```ts
{ id: 'determined', label: 'решимость', status: 'drawn' },
{ id: 'sad',        label: 'грусть',    status: 'planned', shownAs: 'worried' },
```

Нарисованы пять состояний, ещё четыре — `tired`, `sad`, `angry`, `embarrassed` — заказаны
вместе с перерисовкой состава: 12 героев × 9 состояний = 108 изображений.

Каталог спрайтов сцена собирает из файлов `assets/characters/generated/<герой>-<эмоция>-v<версия>.png`,
беря самую свежую версию. Переключать импорты после перерисовки не нужно; исходные листы
и старые версии лежат в `assets/characters/source/` и в сборку не попадают.

Аудит различает два состояния недостающей позы: пока эмоцию никто не играет — это
предупреждение и строка в брифе художнику, как только реплика написана — ошибка, потому
что игрок видит не то лицо, которое задумано.

### Кастинг сквозной новеллы

Одно дело играется в нескольких профессиях, и вместо авторского героя выходит тот, кто есть в
постоянной команде профессии. Правила замены лежат в [src/story/casting.ts](src/story/casting.ts)
и [knowledge/story/casting.json](knowledge/story/casting.json); их читает и приложение, и аудит.

1. авторский герой остаётся, если он есть в команде;
2. замена ищется только среди совпадающих по полу и сюжетной роли (`archetype` в `cast.json`);
3. кандидаты перебираются в порядке `cast.json`, поэтому перестановка состава ничего не меняет;
4. пол без явного значения совместимым не считается;
5. совместимого нет — замены не происходит: на сцене остаётся авторский герой, а аудит показывает
   курс, миссию, сцену, исходного героя и весь доступный состав.

Раньше на месте пятого пункта стоял `targetIds[0]`, и вместо напарницы-стажёра молча выходил
руководитель отдела с её репликой «я сама всё проверила».

### План снижения долга

Базовая линия — не цель, а зафиксированная точка отсчёта: `knowledge/reports/course-audit-baseline.json`.
Порядок этапов выбран по заметности для игрока. Закрытый этап переносит своё правило в
`CRITICAL_RULES` внутри [scripts/audit-course.mjs](scripts/audit-course.mjs) — после этого долг по
нему не сможет вернуться даже через базовую линию.

| Этап | Правила | Сейчас | Чем закрывается |
| --- | --- | ---: | --- |
| 1. Состав профессий | `A1.cast-too-small`, `A1.no-compatible-cast`, `A1.recast-collision` | 15 + 78 + 9 | вырастить состав каждой профессии до 30 персонажей с ролями и полом; и отказы, и склейки героев исчезнут сами |
| 2. Обращение к игроку | `A1.player-gender` | ✅ 0 | закрыт: семь реплик переписаны в форму без рода, правило переведено в `CRITICAL_RULES` |
| 3. Эмоции и спрайты | `A2.pose-planned-in-use`, `A2.blurry` | 5 + 60 | перерисовать состав по брифу [cast-hi-res-v4](assets/image-prompts/cast-hi-res-v4-2026-08-29.md): 12 героев × 9 состояний, фигура от 1350 px. Код готов — новые файлы подхватываются по имени |
| 4. Длина и связность историй | `A4.template-story`, `A4.thin-scenes`, `A4.case-too-short` | 46 + 46 + 46 | переписать дела вручную. `A4.reintroduction` закрыт и переведён в `CRITICAL_RULES`; 22 дела из 68 переписаны, остальные — очередь |
| 5. Последствия выборов | `A4.flag-dangling` | 109 | связать флаги выборов с актами и концовками |
| 6. Педагогика | `A3.explanation-*`, `A3.missing-prerequisite` | 581 | разборы с причиной вместо пересказа условия, объявленные зависимости курсов |

Отдельным пунктом — вынести оставшиеся справочники (эмоции, места действия, размеры вывода) в
машиночитаемые контракты рядом с `routes.json` и `casting.json`. Сейчас аудит вычитывает их
разбором `types.ts`, `Sprite.tsx`, `StoryScene.tsx` и `check-sprites.py`: это честнее, чем копия
таблицы в проверке, но остаётся хрупким.
