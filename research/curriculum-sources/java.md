# Источники: Java

Исследование для отделения языкового ядра от backend-фреймворков.

## Java Programming MOOC — University of Helsinki

- URL: https://java-programming.mooc.fi/, https://java-programming.mooc.fi/part-1,
  https://java-programming.mooc.fi/part-2, https://java-programming.mooc.fi/part-4
- Организация: Хельсинкский университет, департамент компьютерных наук.
- Курс разделён на две последовательности по семь частей: Java Programming I
  (части 1–7) и Java Programming II (части 8–14).
- Часть 1: начало работы → **печать** → чтение ввода → **переменные** →
  вычисления с числами → **условные конструкции** → программирование в обществе.
- Часть 2: повторяющиеся задачи и приёмы → **повторение действий (циклы)** →
  ещё циклы → **методы и деление программы на части**.
- Часть 4: **введение в объектно-ориентированное программирование** → объекты
  в списке → файлы и чтение данных → итог.

**Что взято как curriculum insight.** Это ключевой источник. Классы и объекты
появляются в **четвёртой части**, после печати, ввода, переменных, арифметики,
условий, циклов и методов. То есть студент пишет десятки работающих программ до
того, как впервые объявит класс. Методы вводятся в части 2, до всякого ООП, — как
способ разделить программу, а не как часть объектной модели.

Тот же университет, тот же подход, что и в питоновском MOOC, на который мы уже
опирались: понятия и процедурный код раньше объектов.

**Что не переносилось.** Тексты заданий, система TMC, порядок внутри частей,
привязка к NetBeans.

## Решение по нашему маршруту

Порядок Java Core: типы и переменные → выражения → вывод → условия → циклы →
массивы → методы → параметры → `return` → классы → объекты → коллекции →
исключения → интерфейсы → обобщения → streams.

Обоснование двух решений, расходящихся с прежним содержанием курса:

1. `public class Solution` не может быть первой строкой, которую видит человек.
   У Helsinki класс появляется на четвёртой неделе; у нас он был в миссии 002.
2. `streams` идут последними и только после коллекций и методов — поток без
   понимания коллекции и функции проверяет не ту компетенцию.

Spring и всё, что связано с контейнером зависимостей, остаётся за пределами
языкового ядра: это фреймворк, и он предполагает знание классов, интерфейсов
и обобщений.
