# Синтез: почему первый этап устроен именно так

Документ объясняет порядок тем и выбор типа практики на вводном этапе Data Scientist.
Источники — в [data-scientist.md](./data-scientist.md).

## Правило, из которого всё следует

**Ни одна миссия не может требовать знание, которое ещё не объяснялось.**
Исключение одно: конструкция вводится внутри самой этой миссии, с примером и объяснением.

Это не стилистическое пожелание. Проверка вида «в файле должно быть `def solve(`»
на теме про процессор проверяет не понимание процессора, а знание синтаксиса Python,
которого у человека нет. Такая миссия непроходима честным способом — её можно только
скопировать, не понимая.

## Граф зависимостей вводного этапа

```
что такое программа
  ├─ процессор ──────── ядра и параллельная работа
  ├─ память и диск ──── что где хранится
  └─ файл и путь ────── абсолютный и относительный
        │
        ▼
   терминал ─── текущая папка ─── навигация ─── потоки вывода
        │
        ▼
      git ─── репозиторий и коммит ─── ветки ─── конфликт
        │
        ▼
   Python: вывод ─── переменные ─── арифметика ─── условия ─── циклы
                                                        │
                                                        ▼
                                              строки ─── коллекции
                                                        │
                                                        ▼
                                                    функции
```

Функции стоят в конце цепочки, а не в начале. Это прямо следует из курса Хельсинкского
университета, где определение функций — четвёртый раздел третьей части.

## Когда впервые появляется код

Перед первым пустым редактором человек проходит пять ступеней:

| Ступень | Что делает | Тип миссии |
|---|---|---|
| 1. Увидеть | читает готовую программу и предсказывает вывод | `quiz` с вариантами |
| 2. Понять | получает объяснение и разбирает пример | `story` |
| 3. Изменить | правит одно значение в работающей программе | `lab` с готовым кодом |
| 4. Дополнить | вставляет недостающий фрагмент | `lab` с пропуском |
| 5. Написать | пишет короткую программу сам | `code` |

Первая миссия с пустым редактором в маршруте Data Scientist — **PYC-003**, тридцатая по счёту.
До неё человек уже видел работающий код, менял его и дополнял.

## Как выбирается тип практики

Тип определяется целью обучения, а не квотой на количество кодовых миссий.

| Цель обучения | Тип | Чем проверяется |
|---|---|---|
| Понять устройство или различить сущности | `quiz` | выбор из вариантов |
| Пройти сюжетный поворот, получить объяснение | `story` | выбор или свободный ответ |
| Исследовать рабочую среду | `case` | терминал, свободный ответ |
| Изменить или дополнить готовый код | `lab` | редактор с примером и проверками |
| Написать программу самостоятельно | `code` | редактор, проверки по изученному синтаксису |
| Собрать всё вместе | `boss` | терминал и разбор ситуации |

Ограничение платформы, которое надо признать: сейчас интерфейс умеет три формы
взаимодействия — выбор из вариантов, свободный текст и редактор кода с терминалом.
Настоящей симуляции (перетащить задачи по ядрам, собрать иерархию памяти) в интерфейсе
нет. Пока такие темы разбираются выбором и разбором ситуации; симуляция — отдельная
задача по интерфейсу, а не по контенту.

## Что было не так

Скрипт `enrich-legacy-practice.mjs` добивал каждый курс до 65% кодовых миссий: брал любую
не-сюжетную миссию, назначал тип по чётности индекса и вешал универсальную заготовку
`def solve()` / `return` / `assert`. Ни темы, ни изученного он не знал.

Результат: 1131 миссия из 1683 требовала код, из них 127 требовали конструкции раньше,
чем их объясняли. В маршруте Data Scientist одиннадцать из первых двадцати миссий требовали
`def`, `return` и `assert`, а функциям учили пятнадцатой миссией — которая сама проверялась
функцией.

## Что сделано вместо

1. Реестр навыков `knowledge/skills-registry.json`: для каждой конструкции указано,
   в какой миссии какого курса она вводится.
2. Генератор больше не имеет квоты и не назначает тип по чётности: он подбирает практику
   под тему и проверяет по реестру, что требуемый синтаксис уже введён.
3. Проверка `content:validate` падает, если миссия требует необъяснённую конструкцию.
   Регрессия теперь ломает сборку, а не доезжает до пользователя.
4. Первый этап Data Scientist перепроектирован вручную по ступеням выше.

## Как генератор решает, какой будет практика

После пилота те же правила применены ко всем курсам. Генератор больше не угадывает по
чётности индекса — он проходит четыре проверки по порядку.

**1. Аспект темы.** Почти половина миссий названа по шаблону «Тема: аспект», и аспект прямо
называет цель обучения. Он и определяет форму:

| Аспект | Тип | Почему |
|---|---|---|
| основная идея | `quiz` | понять смысл — узнавание |
| практический выбор | `quiz` | выбрать между вариантами — решение |
| компромиссы | `quiz` | взвесить стороны — решение |
| механика | `lab` | выполнить операцию — производство |
| типичная ловушка | `lab` | воспроизвести ошибку и увидеть её |
| проверка результата | `lab` | убедиться в результате |
| диагностика | `lab` | найти причину в данных |

**2. Среда.** Если тема про терминал, логи, git или инцидент, «руками» означает консоль,
а не редактор: такая миссия получает `case`.

**3. Формулировка задания.** Задание-вопрос при цели вида «различать», «узнавать»,
«объяснять» — это узнавание, а не производство. Такая миссия становится `quiz`.

**4. Порядок выдачи знаний.** Только после выбора типа подбираются проверки — и лишь из
конструкций, введённых раньше по **каждому** маршруту, где встречается курс.

## Три ошибки, которые вскрылись при массовом прогоне

**Реестр был языконезависимым.** Слово `return` считалось питоновскими функциями и в Java,
и в Go. Курсы java-core-jvm, go-production и frontend-quality попадали под правила Python.
Теперь у навыка есть язык, а язык миссии определяется её рабочим файлом (`solution.py`,
`solution.sql`).

**Реляционная модель шла раньше SQL.** В маршрутах java-developer, python-backend и
go-developer курс `relational-databases` стоял до `sql-foundations`, а у devops-engineer
курса SQL не было вовсе — при этом PostgreSQL изучался. Генератор честно снял бы код со
всего курса баз данных. Причина оказалась не в генераторе, а в маршрутах: их порядок
исправлен.

**Битая ссылка в реестре молча отключала навык.** Навык `pandas` указывал на миссию
`PAN-001`, которой не существует (миссии курса — `PDA-*`). Навык никогда не считался
введённым, и pandas терял практику целиком. Теперь `content:validate` падает на любой
битой ссылке реестра.

## Что изменилось в содержании

Затронуто 23 курса из 68. Снят код у 209 миссий, где он проверял не ту компетенцию,
которой учит тема; добавлен у 55, где практики не было вовсе; у 57 сменился тип; у 123
убраны одинаковые проверки, создававшие вид трёх требований вместо одного.

Доля миссий с кодом по всей платформе — 58% (968 из 1683). Раньше было 67% при том, что
127 из них требовали необъяснённый синтаксис. Сейчас таких миссий ноль, и это проверяется
на сборке.

Курс `analyst-metrics` переписан вручную: его миссии шли парами с одинаковым текстом и
обещали автоматические проверки, которых там нет.

## Что осталось

Курсы на Go, Java, JavaScript и в YAML-конфигурациях реестр пока не описывает — для них
порядок выдачи знаний не проверяется. Это следующий шаг: завести навыки этих языков
так же, как заведены питоновские и SQL.
