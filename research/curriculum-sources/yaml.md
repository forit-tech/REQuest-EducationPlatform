# Источники: YAML и конфигурация как код

Исследование для отделения формата от предметных схем (Kubernetes, CI, Compose).

## Ansible — YAML Syntax

- URL: https://docs.ansible.com/ansible/latest/reference_appendices/YAMLSyntax.html
- Организация: Red Hat, официальная документация Ansible.
- Порядок изложения: **списки** (все элементы на одном уровне отступа начинаются
  с `- `) → **пары ключ-значение** (`key: value`) → **вложенность** → сложные
  структуры (списки словарей и наоборот) → **поточный стиль** (сокращённая запись
  в скобках) → **булевы значения** → **многострочные значения** (`|` сохраняет
  переводы строк, `>` склеивает их в пробелы) → **кавычки** → escape-последовательности.
- Отдельно перечислены подвохи: двоеточие с пробелом внутри незакавыченного
  значения ломает разбор; решётка с пробелом начинает комментарий; значение,
  начинающееся с `{`, требует кавычек; строка `true` без кавычек превращается
  в булево; номер версии вроде `1.10` без кавычек становится числом.

**Что взято как curriculum insight.** Формат преподаётся сам по себе, до любой
предметной схемы: сначала как устроены отображение, последовательность, отступ и
кавычки, и только потом — что из этого собирают playbook. Разница между поточным
стилем (`actions: []`) и блочным (`- элемент`) названа явно и является отдельной
темой. Подвохи с кавычками и булевыми значениями — материал для миссий типа
«найди ошибку».

**Что не переносилось.** Модули Ansible, структура playbook, примеры задач.

## Решение по нашему маршруту

**YAML Basics**: скаляр → пара ключ-значение → отступ как вложенность →
вложенное отображение → последовательность → **поточный и блочный стиль** →
кавычки и подвохи типов → многострочные значения → якоря и алиасы.

Только потом предметные схемы отдельными курсами: Docker Compose, CI, Kubernetes.

Это напрямую закрывает нарушение, найденное при инвентаризации: во всех 135
YAML-миссиях стартовый файл показывал `actions: []`, а проверка требовала
блочную последовательность `- "…"`. Переход между двумя стилями записи —
именно та тема, которую источник выделяет явно, а у нас она не объяснялась
нигде.

YAML в реестре навыков должен описываться иначе, чем язык программирования:
у него нет функций и возврата значений, зато есть значимый отступ, два стиля
записи коллекций и приведение типов без объявления. Проверять надо структуру
документа, а не ключевые слова.
