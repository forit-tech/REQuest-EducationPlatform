# Требования вузов — источник правды для трека «Подготовка к магистратуре ML/AI»

Здесь лежат **официальные требования вступительных испытаний**, а не придуманная программа.
Порядок работы жёсткий и обратный привычному:

```
официальные вопросы вуза  →  coverage matrix  →  curriculum  →  уроки и задания
```

Программа не придумывается первой. Любой урок трека обязан ссылаться на пункт требований
либо на явно записанное обоснование, почему темы нет во вступительном, но она нужна
профессионально (`justification`).

## Классы источников

Совпадают с `knowledge/content-factory/sources.json`:

- `GROUNDING` — официальная документация и материалы вуза. Только сверка фактов и определений. Пересказ и перенос формулировок запрещены.
- `ADAPTABLE_OER` — открытая лицензия, можно адаптировать и переводить с атрибуцией.
- `REFERENCE_ONLY` — ориентир по программе, глубине и типам упражнений. Содержание не переносится.

Официальные списки вопросов вузов хранятся дословно как **требование**, а не как учебный
материал: по ним строится проверка покрытия. Формулировки заданий REQuest должны быть
оригинальными.

## Статусы покрытия

Поле `coverage.status` у каждого требования:

| Статус | Смысл |
|---|---|
| `not-covered` | Ничего нет |
| `partial` | Тема упоминается, но глубины устного ответа нет |
| `covered` | Есть урок, задания нужных типов и проверка |
| `out-of-scope` | Сознательно не закрываем, причина в `coverage.note` |

Переводить требование в `covered` вручную нельзя: статус выставляет скрипт проверки по
фактически существующим урокам и заданиям.

  теста и маршруты в обход экзамена. Детализация — по демоверсии от вуза.
