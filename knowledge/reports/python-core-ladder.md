## 3. Три миссии под особой проверкой

### PYC-003 — `int()`, `*`, преобразование строки в число

Стартовый файл: две переменные и `# TODO: преобразуй цену, посчитай total и выведи его`.
Комментарий кодом не является, значит по спецификации это **пустой редактор**.

`int()` до этого места не показан ни разу: в PYC-001 в объяснении сказано «цену нужно явно
преобразовать в int» — это называние, а не показ. `*` показан в PYC-001 ровно один раз, и
показан как **дефект** («умножение строки повторяет текст»); умножение чисел не вводилось нигде.

Подсказка: «Начни со строки `price = int(price_raw)`». Проверка: `includes: "price = int(price_raw)"`.
Подсказка и проверка совпадают посимвольно — миссия решается копированием подсказки
и не отличает понявшего от скопировавшего.

### PYC-004 — `if`, `==`, `:`, отступ, `else`

Пять новых сущностей. Из трёх проверок две (`if `, `print(`) выполнены стартовым файлом:
реальное требование миссии — набрать `else:`. Смену `status` на `"paid"`, которую просит
формулировка, не проверяет ничего.

`objectives` миссии — «пройти по списку словарей циклом / отобрать записи условием /
накопить счётчик». Ни списков, ни циклов, ни словарей в миссии нет: метаданные от другой миссии.

### PYC-005 — список, `for`, `in`, счётчик, вложенный `if`

Шесть новых сущностей. Проверка «Список обходится циклом» (`includes: "for "`) выполнена
комментарием `# for status in statuses:` в стартовом файле. Обе недостающие строки выданы
подсказками дословно (`paid_orders = paid_orders + 1` и заголовок цикла).

`objectives` — «отделять успешный запуск от корректного результата / выбирать минимальную
проверку перед публикацией». Это цели миссии про тестирование, не про цикл.

## 5. Почему `npm run api:audit` показывает по этим миссиям ноль

Аудит находит 9 нарушений в `python-core` — и все в PYC-013, 015, 017, 048.
На PYC-003/004/005 он молчит по трём причинам, каждая из которых чинится:

1. **Комментарий считается кодом.** `requiredBy()` снимает требование, если токен есть
   в `starterCode` — обычной подстрокой. `# for status in statuses:` делает `for`
   и показанным, и невостребованным. То же с `else` в PYC-004.
2. **Упоминание в подсказке считается показом.** `surfaceOf()` включает `hints` и
   `explanation`, поэтому «преобразовать в int» из PYC-001 закрывает `int()` для всего курса.
3. **Правило `independent-use-right-after-first-sight` существует, но из-за (1) и (2)
   на этом курсе не срабатывает ни разу** — то, что оно должно было поймать, уже отфильтровано.

**Починено.** Все три дыры закрыты следующим коммитом, правила покрыты golden set
(`npm run api:audit:test`). По каталогу: `required-before-shown` 40 → 55,
`independent-use-right-after-first-sight` 93 → 94, `multiple-new-apis-at-once`
37 → 43, `blank-editor-task` 107 → 112, новое правило `check-passes-on-starter` —
140 находок, новое правило `hint-is-not-teaching` — 12, из них 9 критических.

По `python-core` было 9 находок, стало 21. Три миссии этого раздела теперь
видны машине:

| Миссия | Что фиксирует аудит |
|---|---|
| PYC-002 | `check-passes-on-starter`: 1 из 2 проверок выполнена стартовым файлом |
| PYC-003 | `required-before-shown` для `int()` — «названо словом, синтаксис не показан»; `hint-is-not-teaching`, критическое |
| PYC-004 | `independent-use-right-after-first-sight` для `else`; `check-passes-on-starter`: 2 из 3 |
| PYC-005 | `independent-use-right-after-first-sight` для `for`; `check-passes-on-starter`: 1 из 3, выполнена комментарием |

## 6. Предлагаемый curriculum diff

Правило, по которому построен диф: **одна новая сущность на миссию**; вторая допустима,
только если она синтаксическая часть первой и отдельно не имеет смысла
(`if` вместе с `:` и отступом — можно; `if` + `else` + `==` — нельзя).

### Остаётся

| Миссия | Что поменять |
|---|---|
| PYC-001 | остаётся завязкой. Из объяснения убрать имя `int`: причина ошибки формулируется как «строка ведёт себя не как число». Называть будущую функцию раньше её лестницы не нужно |
| PYC-002 | остаётся. Заменить проверку `includes: "="` на непредвыполняемую |

### Переносится

Ничего не переносится как есть. PYC-003, PYC-004 и PYC-005 в нынешнем виде — это
финальные `transferred`-кейсы своих лестниц, а не первое знакомство. Они встают
в конец соответствующих блоков, а перед ними появляются недостающие ступени.

### Разбивается

| Было | Становится | Новая сущность на шаг |
|---|---|---|
| PYC-003 | 4 миссии лестницы `int()` + 4 миссии лестницы `*` + кейс | `int()`; затем `*` |
| PYC-004 | сравнение → `if` → `else` = 3 лестницы, 9–10 миссий | `==` и `True`/`False`; `if` с `:` и отступом; `else` |
| PYC-005 | список → `for` → счётчик → вложенность = 4 лестницы, 11–13 миссий | список; `for`+`in`; накопление; вложенный блок |

### Удаляется как пустое или неотличимое

- PYC-007…010, PYC-012…015, PYC-017…020 — 12 миссий с пустым редактором
  и без предметного задания;
- PYC-006, PYC-011, PYC-016 — шаблонные квизы, их место занимают настоящие
  `explained`-миссии соответствующих лестниц;
- PYC-018…020 в любом случае дубли PYC-017.

Дальше PYC-021…050 — тот же шаблон на семи темах. Их разбор в этот отчёт не входит.

### Новые вводные миссии, которых сейчас нет ни одной

Каждая вводит ровно одну сущность, каждая по лестнице
`explained → shown → guided → modified → filled → independent`:

`int()` · `*` · `-` · `/` · `==` · булев результат · `if` (с `:` и отступом) ·
`else` · `elif` · список · индекс · `len()` · `for`+`in` · накопление счётчика ·
вложенное условие · `while` · метод объекта (на `.append()`) · строковые методы ·
словарь · `def` · `return` · область видимости · файлы · `import` · исключения · `assert`

## 7. Целевой порядок

```
строки и числа → int()/float() → арифметика по одному оператору →
сравнения → булев результат → if → else → elif →
списки → индекс → len() → for → накопление счётчика → вложенное условие → while →
строковые методы → словарь → функции → return → область видимости →
файлы → импорт и модули → ошибки и исключения → тесты
```

Оценка объёма: первые четыре блока (до `while` включительно) — примерно 45–55 миссий
против нынешних пяти содержательных. Это соответствует плотности `python-first-steps`,
где на `print` и переменную ушло 20 миссий.
