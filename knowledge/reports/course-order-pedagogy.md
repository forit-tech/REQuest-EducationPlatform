# Порядок курсов в маршрутах: педагогический разбор

Проверка не про отдельные миссии, а про то, как курсы стоят друг за другом в
пятнадцати маршрутах профессий. Вопрос один: доходит ли человек до каждого
следующего курса с тем, что этот курс от него требует.

Источник правил — `PROGRAMMING_PEDAGOGY.md`. Данные собраны из
`knowledge/professions/programs.json`, `course.json` каждого курса,
`knowledge/reports/api-introduction.json` и `knowledge/reports/course-quality.json`
на текущем состоянии `main`.

## Коротко

Порядок курсов внутри маршрутов в целом осмысленный: зависимости объявлены,
граф связный, циклов нет, `curriculum:validate` проходит. Но лестница входа
построена ровно для одного языка из шести, а автоматический контроль порядка
знаний видит меньше трёх четвертей кодовых миссий платформы.

| Находка | Масштаб |
|---|---|
| Лестница входа есть только у Python | 3 языка из 4 проверяемых входят без неё |
| Первый курс всех маршрутов — питоновский | 15 маршрутов из 15, включая Java, Go, frontend, DevOps, ИБ |
| Аудит не видит SQL и YAML | 314 кодовых миссий из 1077 вне проверки |
| Пять профессий проходят целиком вне аудита | devops, sre, cybersecurity, pentester, soc |
| `import` не введён до NumPy и Pandas | 105 кодовых миссий с пустым редактором подряд |
| Хвост маршрута — заготовка или фальшивая практика | 56 курсов из 75 |
| Уровень откатывается назад внутри маршрута | 12 переходов в 8 маршрутах |

## Что устроено правильно

Это стоит зафиксировать отдельно, потому что дальше идёт список проблем.

**Питоновский вход починен и работает.** `python-first-steps` стоит
непосредственно перед `python-core` во всех шести маршрутах, где Python нужен,
и у него ноль нарушений по всем шести правилам аудита. Это единственное место
на платформе, где вход в язык описан лестницей.

**Зависимости объявлены и проверяются.** `curriculum:validate` держит граф
связным, `content:validate` ловит навык, введённый позже первого использования
(на этой неделе поймал именно такой случай в `python-core`).

**Порядок внутри SQL-ветки логичен.** `sql-foundations` → `advanced-sql` →
`relational-databases` → `postgresql` → `analytical-databases` → `clickhouse`
идёт от языка запросов к устройству хранилищ, а не наоборот.

## 1. Лестница входа построена только для Python

Вход в язык — самое дорогое место маршрута: человек впервые видит код этого
языка. Сравнение четырёх входов, которые аудит умеет проверять:

| Язык | Курс входа | Миссий | Кодовых | Требует непоказанное | Больше одной новой сущности |
|---|---|---:|---:|---:|---:|
| Python | `python-first-steps` | 27 | 19 | 0 | 0 |
| Java | `java-core` | 17 | 13 | 5 | 7 |
| Go | `go-core` | 16 | 12 | 2 | 6 |
| JavaScript | `javascript-core` | 19 | 14 | 2 | 6 |

У Java на 13 кодовых миссий приходится 7 перегруженных: больше половины
практики вводит сразу несколько незнакомых сущностей. Первое требование —
`System.out.println()`, названное словом, но не показанное синтаксисом. Это
ровно тот диагноз, из-за которого для Python и был написан
`python-first-steps`.

Ни у одного из трёх языков нет курса-предшественника: в маршруте они стоят
сразу после `technical-foundations`.

**Что делать.** По одному курсу входа на язык, по образцу `python-first-steps`:
`java-first-steps`, `go-first-steps`, `javascript-first-steps`. Порядок введения
для каждого уже описан в `PROGRAMMING_PEDAGOGY.md` в таблице «Правила для
остальных технологий».

## 2. Первый курс всех пятнадцати маршрутов — питоновский

`technical-foundations` объявлен как `technology: "python"` и содержит две
кодовые миссии на `solution.py`. Стоит он первым во всех пятнадцати маршрутах —
включая `java-developer`, `go-developer`, `frontend-developer`,
`react-developer` и все пять маршрутов эксплуатации и безопасности.

Для будущего Java-разработчика это значит, что первый код, который он видит на
платформе, написан на языке, которого в его маршруте больше не будет. Для
DevOps-инженера — что единственные две кодовые миссии его фундамента тоже
питоновские, хотя дальше идёт YAML.

Хуже того, эти две миссии стоят в маршруте **до** `python-first-steps` — то
есть до лестницы, ради которой та и написана. `TECH-014` «Первая программа:
вывод и переменная» начинает с пустого редактора и требует написать `print()`
и `=` одновременно, причём обе сущности человек видит впервые. Аудит выдаёт на
неё четыре находки из шести возможных. В `TECH-015` две проверки из трёх
выполнены стартовым файлом ещё до действий ученика.

Получается, что первая программа на платформе написана с нуля и без объяснений,
а аккуратный разбор `print` начинается только курсом позже.

**Что делать.** Либо снять с `technical-foundations` язык и код целиком,
оставив его концептуальным курсом (`PROGRAMMING_PEDAGOGY.md` прямо разрешает
темы без кода), либо развести его на языковые варианты. Первое дешевле и
честнее: технический фундамент — про то, как устроены файл, процесс и сеть,
а не про синтаксис конкретного языка.

## 3. Аудит не видит SQL и YAML

`scripts/audit-api-introduction.mjs` пропускает курс, если у языка нет словаря
ключевых слов (`if (!language || !KEYWORDS[language]) continue`). Словари
заведены для четырёх языков: Python, JavaScript, Go, Java.

Кодовые миссии платформы по языкам:

| Язык | Кодовых миссий | Под аудитом |
|---|---:|---|
| Python | 609 | да |
| SQL | 171 | **нет** |
| YAML | 143 | **нет** |
| JavaScript | 72 | да |
| Go | 42 | да |
| Java | 40 | да |
| Всего | 1077 | 763 из 1077 |

314 кодовых миссий — 29% — не проверяются вообще ничем из шести правил. Это не
теоретический пробел: `sql-foundations` содержит 39 миссий со стартовым файлом
`solution.sql`, а `yaml-basics` — 8 со стартовым `config.yaml`, и порядок
введения `SELECT`, `WHERE`, `GROUP BY` или отступов YAML никем не проверен.

Последствие в маршрутах: пять профессий из пятнадцати — `devops-engineer`,
`sre-engineer`, `cybersecurity-specialist`, `pentester`, `soc-analyst` —
проходят почти целиком по курсам, объявленным как YAML, и не попадают в аудит
ни одной миссией, кроме `technical-foundations`.

**Что делать.** Завести словари для SQL и YAML в `scripts/audit/introduction.mjs`.
Для SQL это ключевые слова запроса, для YAML — отступ, ключ, список и якорь.
Работа небольшая, а закрывает она треть кодовой практики платформы.

## 4. Разрыв между `python-core` и NumPy остаётся главным

Это уже известная дыра, но здесь виден её масштаб в маршруте.

`data-scientist` идёт `python-core` (позиция 3) → `data-foundations` →
`data-formats` → `numpy` (позиция 6) → `pandas` (позиция 7). Слова `import`
в `python-core` нет ни разу: блок про модули стоит в плане второго курса,
уровня «Средний», которого ещё нет.

| Курс | Кодовых миссий | Из них с пустым редактором |
|---|---:|---:|
| `numpy` | 32 | 32 |
| `pandas` | 73 | 73 |

Сто пять кодовых миссий подряд начинаются с файла, в котором нет ни одной
исполняемой строки, — и первая же из них, `NPY-002`, требует написать `import`,
`as`, `np.array()` и `assert` одновременно.

**Что делать.** Порядок уже описан в `python-core-curriculum.md`: блок «Модули»
второго курса обязан встать в маршрут перед NumPy. До этого NumPy переписывать
бессмысленно — лестница обвалится на первой же строке импорта.

## 5. Хвост каждого маршрута — заготовка

Классификация всех 75 курсов:

| Класс | Курсов |
|---|---:|
| `AUTHORED_REAL` | 14 |
| `AUTHORED_NEEDS_REVIEW` | 5 |
| `GENERATOR_SCAFFOLD` | 31 |
| `FAKE_PRACTICE` | 25 |

Пятьдесят шесть курсов из семидесяти пяти — заготовка генератора или
практика, которая проверяет не поведение программы. Типичная запись
классификатора для курса из класса `FAKE_PRACTICE`: «9 из 9 практических миссий
проверяют русский литерал, а не поведение».

В маршрутах это распределено неравномерно и предсказуемо: чем дальше от начала,
тем хуже. Профессиональные этапы почти целиком состоят из курсов ровно на 13
миссий, из которых 9 кодовых, — это подпись генератора.

| Маршрут | Курсов | Из них заготовок |
|---|---:|---:|
| `data-engineer` | 15 | 6 |
| `data-scientist` | 17 | 5 |
| `devops-engineer` | 8 | 4 |
| `sre-engineer` | 6 | 4 |
| `cybersecurity-specialist` | 6 | 4 |
| `pentester` | 8 | 4 |
| `soc-analyst` | 6 | 4 |
| `data-analyst` | 12 | 3 |

У четырёх маршрутов эксплуатации и безопасности заготовки составляют от
половины до двух третей всего пути.

**Что делать.** Это самый большой кусок работы на платформе, и делать его
раньше фундамента нельзя: переписанный курс про Kubernetes поверх
непроверенного YAML-входа даст тот же результат, что идеальный NumPy поверх
кривого `print`.

## 6. Уровень внутри маршрута откатывается назад

Двенадцать переходов в восьми маршрутах ведут с более высокого уровня на более
низкий. Часть из них законна, часть — нет, и различие проходит по одной черте:
меняется ли вместе с уровнем предметная область.

**Законные откаты** — переход в другую область, которая начинается с нуля:

- `data-analyst`: `advanced-sql` (Средний) → `python-first-steps` (Старт).
  Человек закончил SQL и начинает Python с нуля — это правильно, а не ошибка.
- `data-engineer`: `clickhouse` (Продвинутый) → `etl-elt` (Средний).

**Сомнительные откаты** — та же область, уровень назад:

- `data-scientist` и `ai-engineer`: `python-core` (База) → `data-foundations`
  (Старт). Курс уровня «Старт» стоит после курса уровня «База» внутри одной
  линии данных.
- `data-analyst`: `statistics` (Средний) → `data-visualization` (База).
- `pentester`: `pentest-methodology` (База) → `javascript-core` (Старт) — здесь
  область действительно меняется, но вход в JavaScript, как показано в разделе 1,
  сам по себе лестницы не имеет.

**Что делать.** Уровень курса — обещание человеку, а не тег. Там, где область
не меняется, порядок стоит выровнять; там, где меняется, — сделать смену явной
в тексте этапа, чтобы «Старт» на шестом шаге читался как начало новой темы,
а не как понижение.

## Порядок починки

Снизу вверх, потому что каждый следующий пункт опирается на предыдущий.

0. ~~**Сделать аудит воротами сборки.**~~ Сделано: `npm run api:audit` входит
   в `npm run build` и падает на ухудшении относительно зафиксированного долга.
   Без этого любой следующий пункт можно молча откатить назад.
1. **Достроить `python-core`** до конца «Базы» и написать второй курс до блока
   «Модули». Без `import` не чинится ни NumPy, ни Pandas, а это 105 миссий
   в самых населённых маршрутах.
2. **Завести словари SQL и YAML в аудите.** Дёшево, и сразу видно состояние
   трети кодовой практики, которая сейчас невидима.
3. **Снять код с `technical-foundations`** или развести курс по языкам.
4. **Написать курсы входа** для Java, Go и JavaScript по образцу
   `python-first-steps`.
5. **Переписывать профессиональные курсы** — только после того, как под каждым
   из них есть проверенный языковой фундамент.
