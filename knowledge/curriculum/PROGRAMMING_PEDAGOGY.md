# Педагогика программирования REduQuest

Источник правил для всего, что просит человека написать код. Документ обязателен
при создании и переработке курсов; на модель данных в `course.json` он пока не
влияет — сначала по нему пишутся курсы, и только потом правила закрепляются
схемой.

## Главный закон

**Ни одна миссия не вправе требовать написать конструкцию, функцию, метод,
оператор, класс, модуль, библиотеку, CLI-команду или ключ конфигурации, которых
человек до этого нигде не видел и которые ему не объяснили.**

Упоминание названия технологии обучением не является. «NumPy нужен для работы с
числами» — это не знакомство с `np.array()`. Если человек может решить задание
только поиском в интернете, курс на этом месте не учит, а проверяет умение
искать.

## Исходное предположение

Курс пишется для человека, который может:

- никогда не видеть кода;
- не знать, что такое язык программирования;
- не знать, где код пишут и что такое файл программы;
- не знать, что значит «запустить код»;
- не знать, что такое синтаксис, функция, аргумент, переменная, ошибка.

Из этого следует, что очевидным не считается ничего. Кавычка, скобка, отступ и
знак равенства — это отдельные сущности, которые вводятся явно. Опытному
человеку такой темп не мешает: он проходит стадии знакомства быстро, но они
существуют.

## Стадии знакомства

```
explained → shown → guided → modified → filled → independent → debugged → transferred
```

| Стадия | Что происходит |
|---|---|
| `explained` | сказано, что это за сущность и зачем она нужна |
| `shown` | показана целиком в рабочем коде, разобран каждый незнакомый символ |
| `guided` | человек запускает готовое и видит результат |
| `modified` | меняет одно известное значение внутри готового |
| `filled` | вставляет пропущенный фрагмент из уже разобранных |
| `independent` | пишет сам с чистого места |
| `debugged` | чинит сломанное с этой конструкцией |
| `transferred` | применяет вместе с ранее изученным в мини-кейсе |

Проходить все стадии не обязательно. Обязателен порядок: **`independent` не
может наступить раньше, чем пройдены `explained`, `shown` и хотя бы одна из
`modified` / `filled`.**

Это концептуальная модель, а не обязательная схема production. Поля `requires`
и `stages` в `course.json` не введены; 1765 существующих миссий продолжают
работать без них. Стадии описывают, как проектировать курс, а не как хранить
его на диске.

## Таксономия: что вводится отдельно

Для новичка это разные механизмы, и знание одного не даёт знания другого.
Человек, умеющий вызвать `print()`, не умеет автоматически вызвать
`text.strip()` — там другое устройство записи.

| Вид | Пример | Что объяснить до требования |
|---|---|---|
| синтаксис | кавычки, скобки, отступ, запятая, двоеточие | что это часть языка, а не текст |
| оператор | `+` `-` `*` `/` `=` `==` `%` | что делает и к чему применяется |
| встроенная функция | `print()` `input()` `len()` `type()` | что такое функция, аргумент, возврат |
| метод объекта | `text.strip()` `names.append()` | что метод принадлежит объекту |
| атрибут | `array.shape` `df.columns` | почему без скобок — это не вызов |
| модуль и библиотека | `import numpy as np` | что бывает чужой готовый код и короткое имя |
| функция библиотеки | `np.sqrt()` `pd.read_csv()` | что имя через точку — путь к функции внутри |
| класс | `class Order:` | что это описание, а не действие |
| своя функция | `def solve():` | определение против вызова |
| CLI-команда | `git commit` `docker run` | что такое команда, аргумент, флаг |
| ключ конфигурации | `replicas:` в YAML | что файл описывает желаемое состояние |

Каждый вид вводится своей миссией знакомства. Нельзя ввести «функции вообще» и
считать, что тем самым введены методы и функции библиотек.

## Concept before syntax

Сначала причина, потом запись. Конструкция появляется как ответ на проблему,
которую человек уже почувствовал.

Неправильно: «Переменная — это именованная область памяти. Напиши
`city = "Москва"`».

Правильно:

```python
print("Москва")
print("Москва")
print("Москва")
```

«Город повторяется трижды. Поменяется город — править в трёх местах. Как дать
значению имя один раз?» И только теперь:

```python
city = "Москва"
```

с разбором: `city` — имя, `=` — сохранить под именем, `"Москва"` — значение.
Отдельно проговаривается, что `=` здесь не «равно».

## Одна новая сущность за раз

На уровнях «Старт» и «База» миссия вводит **ровно одну** новую сущность.
Остальное в задании должно быть уже пройдено.

Комбинировать известное с одним новым — можно и нужно: именно так проверяется,
что старое усвоено. Задание «сложи два числа и извлеки корень» допустимо, если
переменные, `+` и `print` пройдены, а `np.sqrt()` введён шагом выше.

На уровнях «Средний» и «Продвинутый» порог мягче, но правило показа остаётся:
новое всё равно вводится до требования.

## Exposed knowledge и required knowledge

Различаются два понятия:

- **required knowledge** — то, что человек обязан написать сам;
- **exposed knowledge** — то, что он вообще видит в коде на экране.

Формально не требовать написать `Path` ещё не значит, что нагрузки нет. Такой
стартовый файл для новичка непроходим, даже если менять надо одну строку:

```python
from pathlib import Path

data = Path("data.txt").read_text(encoding="utf-8")
```

Здесь сразу четыре незнакомых механизма: импорт из модуля, класс `Path`, метод
`.read_text()` и именованный аргумент. Человек не понимает, что перед ним
происходит, и меняет строку вслепую.

На beginner-уровне любая конструкция в стартовом файле должна:

- быть объяснена в этой же миссии, **либо**
- быть уже известна по предыдущим миссиям, **либо**
- быть явно помечена как инфраструктура и скрыта от глаз ученика.

Инфраструктурой считается то, что к теме миссии отношения не имеет: загрузка
готового набора данных, вывод результата в проверяемом формате, служебный
идентификатор дела. Такое допустимо не показывать, но нельзя оставлять на
экране без пометки.

## Пустой редактор

Задание «напиши с нуля» допустимо только после того, как конструкция прошла
`shown → modified → filled`. До этого стартовый файл содержит рабочий код.

Комментарий кодом не является. Файл из трёх строк вида
`# TODO: собери массив и проверь форму результата` — это пустой редактор.

## Концептуальные темы не обязаны содержать код

Процессор, ядро, поток, процесс, кеш, память, сеть, задержка, отказоустойчивость
изучаются показом, симуляцией, разбором случая и квизом. Редактор кода в такой
теме появляться не должен.

Требование «в профессиональном блоке практика не меньше 65% миссий» выполняется
за счёт симуляций, разборов и кейсов, а не за счёт того, что к теме про ядра
приделывают редактор. Практикой считается любое действие ученика, а не только
набор текста программы.

Код появляется только там, где уже выбран язык и введён конкретный инструмент
для решения. Тема «параллельные вычисления» сначала объясняет независимые
задачи и ядра без кода; `concurrent.futures` и `ThreadPoolExecutor` вводятся
позже и по отдельности, в курсе конкретного языка.

## Полная лестница: `print`

Эталон плотности. Один модуль, одна сущность, самостоятельное написание — на
девятом шаге.

| Шаг | Стадия | Что происходит |
|---|---|---|
| 1 | `explained` | Функция — готовое действие с именем; ты передаёшь ей данные. Термин «функция» вводится здесь |
| 2 | `shown` | `print("Привет")` с разбором: `print` — имя, `()` — что передаём, `"` — границы текста |
| 3 | `guided` | Запустить готовый файл, увидеть `Привет`. Ничего не писать |
| 4 | `modified` | Заменить текст в кавычках на своё слово |
| 5 | `modified` | Заменить двойные кавычки на одинарные, убедиться, что результат тот же |
| 6 | `modified` | Добавить вторую строку вывода по образцу первой |
| 7 | `debugged` | Починить `print("Привет"` — не закрыта скобка. Показать сообщение об ошибке |
| 8 | `filled` | Дополнить `____("Привет")` |
| 9 | `independent` | Первая пустая строка: вывести слово «Москва» |
| 10 | `transferred` | Мини-кейс: три строки приветствия подряд |

## Полная лестница: переменная

| Шаг | Стадия | Что происходит |
|---|---|---|
| 1 | `explained` | Проблема: `"Москва"` повторяется в трёх `print` |
| 2 | `shown` | `city = "Москва"` с разбором имени, `=` и значения |
| 3 | `shown` | `print(city)` — почему без кавычек; рядом `print("city")` и разница в выводе |
| 4 | `guided` | Запустить готовую программу из двух строк |
| 5 | `modified` | Изменить значение — увидеть, что вывод поменялся в трёх местах сразу |
| 6 | `debugged` | Починить `print("city")` вместо `print(city)` |
| 7 | `filled` | Дополнить пропущенное имя слева от `=` |
| 8 | `independent` | Сохранить своё имя в переменную и вывести |
| 9 | `transferred` | Кейс: две переменные, три строки вывода |

## Полная лестница: библиотека и импорт

Библиотека и импорт — два разных незнакомых механизма, а не один. Они вводятся
до любой конкретной библиотеки, на встроенном модуле.

| Шаг | Стадия | Что происходит |
|---|---|---|
| 1 | `explained` | До сих пор всё писалось с нуля. Часть задач решена другими и оформлена как библиотека |
| 2 | `shown` | `import math` и `print(math.pi)` — короткий пример на встроенном модуле |
| 3 | `explained` | Разбор: `import` — подключить, `math` — имя модуля, точка — путь внутрь |
| 4 | `guided` | Запустить готовое |
| 5 | `modified` | Заменить `math.pi` на `math.e` |
| 6 | `transferred` | Квиз: что делает строка `import` |

Короткое имя вводится отдельным шагом, уже на конкретной библиотеке:
`import numpy as np`, где новое — только `as`.

## Эталон введения библиотеки: NumPy

Порядок обязателен:

```
что такое библиотека → import → alias → np.array → shape →
indexing → arithmetic → aggregation → sqrt
```

Каждый шаг — отдельный модуль по лестнице выше. К моменту, когда появляется
`np.sqrt()`, человек уже знает переменные, `+`, `print`, `import`, `np` и
`np.array()`. Поэтому итоговое задание содержит ровно одну новую вещь:

```python
a = 9                     # переменная — модуль Python
b = 16                    # число — модуль Python
result = np.sqrt(a + b)   # + известен, np.sqrt введён шагом выше
print(result)             # print — первый модуль Python
```

## Неправильное задание и его переработка

Реальный пример из каталога — `NPY-002`.

**Было.** Вводная объясняет идею словами и не содержит ни строчки кода: «Список
Python хранит указатели на отдельные объекты, разбросанные по памяти. Массив
NumPy хранит сами значения подряд». Стартовый файл — три строки комментариев.
Автоматическая проверка требует написать `import numpy as np`, `np.array(` и
`assert`.

Почему это тупик: слово `import` не встречается в курсе `python-core` ни разу, а
именно он стоит перед NumPy во всех маршрутах. Четыре новые сущности сразу,
пустой редактор, предварительного показа нет.

**Стало.** Пять модулей вместо одной миссии:

| Модуль | Новое | Первое самостоятельное написание |
|---|---|---|
| Что такое библиотека | модуль, подключение | нет, только квиз |
| Подключить NumPy | `as` и короткое имя | строка импорта |
| `np.array()` | функция библиотеки | массив из своих чисел |
| `.shape` | атрибут без скобок | форма своего массива |
| `np.sqrt()` | функция библиотеки | корень суммы двух чисел |

## Правила для остальных технологий

Порядок введения. В каждой строке — обязательная последовательность, внутри
которой действует та же лестница.

| Технология | Порядок |
|---|---|
| Pandas | библиотека → `read_csv` → что такое DataFrame → `head` → выбор колонки → фильтр → новая колонка → пропуски → `groupby` → `merge` |
| sklearn | что такое модель как объект → общий договор `fit` / `predict` → конкретная модель → метрика → разделение выборки → подбор параметров |
| React | что такое импорт → компонент как функция → JSX → props → событие → `useState` как функция, возвращающая пару → сеттер → эффект |
| Go | пакет и `func main` → вывод → переменные → функции → срезы → карты → структуры → методы → интерфейсы → горутины и каналы |
| Java | рамка `class` + `main` как данность с обещанием разобрать позже → вывод → переменные → условия → циклы → методы → классы → коллекции → обобщения |
| SQL | что такое таблица и строка → `SELECT` одной колонки → несколько колонок → `WHERE` → сортировка → агрегаты → `GROUP BY` → соединения |
| CLI | что такое команда → команда без аргументов → аргумент → флаг → путь → перенаправление → конвейер |
| YAML | что файл описывает состояние → ключ и значение → вложенность отступом → список → ссылка на ключ из документации инструмента |

Для Java допускается ввести рамку `public class ... { public static void main }`
как данность, если явно сказано, что это рамка и она будет разобрана отдельной
миссией. Молча оставлять непонятное нельзя.

## Запрещено

- Пустой редактор до того, как сущность прошла `shown → modified → filled`.
- Больше одной новой сущности в миссии на уровнях «Старт» и «База».
- Заглушки вида `build_plan()` / `buildPlan()` с полями `artifact` и `steps`.
- Русская строка-литерал как доказательство решения: проверка обязана проверять
  поведение программы, а не формулировку, вписанную в кавычки.
- Автоматическая проверка, которая уже выполнена стартовым файлом.
- Универсальная тройка «Сцена → Код → Лаборатория» на каждую тему: набор
  взаимодействий определяется темой, а не шаблоном.
- Код в концептуальной теме.

## Предложение: `unexplained-api-in-starter`

Будущее предупреждение для `npm run api:audit`. **В аудит пока не внедрено.**

Сейчас скрипт разбирает `required knowledge` — то, что человек обязан написать
по автоматическим проверкам. Данные для второй половины у него уже есть:
`surfaceOf()` собирает всё показанное, `requiredBy()` — только требуемое.

Предлагаемое правило: если в стартовом файле встречается конструкция, которая не
объяснена в этой миссии, не введена раньше в маршруте и не помечена как
инфраструктура, — выдать предупреждение.

Уровень зависит от курса: на «Старте» и «Базе» ошибка, дальше предупреждение. На
продвинутых уровнях каркас законно содержит инфраструктуру будущего решения, и
жёсткий запрет там мешал бы.

Для пометки инфраструктуры понадобится необязательное поле у миссии — например
список строк или диапазонов стартового файла, которые ученику показывать не
нужно. Вводить его следует вместе с правилом, а не заранее.

## Порядок применения

1. Эта спецификация.
2. Пилот Python Basics: первые модули вручную по лестнице.
3. Валидатор `exposed knowledge` по разделу выше.
4. Пилот NumPy.
5. Pandas.
6. Остальные курсы по очереди из отчёта о происхождении содержания.

Идеальный NumPy поверх кривого знакомства с `print`, `input` и переменными
фундамента не даёт.
