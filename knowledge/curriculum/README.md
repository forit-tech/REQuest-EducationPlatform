# REduQuest Careers — учебный граф

Это источник правды для программы обучения. Не «список миссий», а граф:

```
блок → профессия → этап → курс → модуль → тема → миссии
```

Курс существует **один раз** и переиспользуется профессиями. Разная глубина — это
разные курсы (`sql-core` ≠ `sql-analytics` ≠ `db-indexes`), а не один курс «SQL»,
который все проходят одинаково.

## Файлы

| Файл | Что описывает |
|---|---|
| `blocks.json` | Направления: разработка, данные, AI, системы, ИБ, QA, мобильная, архитектура |
| `professions.json` | 18 профессий: блок, цель, этапы, порядок курсов, составные пути |
| `courses/*.json` | Курсы с модулями, уровнями, навыками и зависимостями |

## Уровни (`level`)

| Уровень | Смысл |
|---|---|
| 0 | Общий фундамент: компьютер, IDE, git, алгоритмическое мышление |
| 1 | Язык и синтаксис с нуля, первые самостоятельные программы |
| 2 | Рабочие инструменты профессии, типовые задачи |
| 3 | Инженерная глубина: архитектура, производительность, надёжность |
| 4 | Production: эксплуатация, безопасность, стоимость, мониторинг |
| 5 | Итоговый проект профессии |

## Зависимости не блокируют

`prerequisites` — это «что стоит знать заранее», а не замок. **Любой курс можно начать
в любой момент.** Граф зависимостей задаёт рекомендуемый порядок и позволяет показать
человеку, чего ему будет не хватать, но ничего не запирает.

Поэтому `npm run curriculum:validate` на курс, стоящий в маршруте раньше своей базы,
выдаёт предупреждение, а не ошибку. Ошибками остаются только поломки графа:
несуществующие ссылки, дубли идентификаторов и циклы.

## Стандарт модуля

Каждый модуль проходится одинаково:

1. **Часть истории** — зачем это понадобилось в деле профессии.
2. **Короткая теория `.md`** — ровно та порция, что нужна сейчас, с примером кода.
3. **Посмотри код** — что он выведет.
4. **Измени код** — поменяй одно значение.
5. **Дополни** — вставь пропущенный фрагмент.
6. **Напиши сам** — маленькая задача целиком.
7. **Найди ошибку** — сломанный код.
8. **Квиз** — проверка понимания, а не памяти.
9. **Мини-кейс** — вместе с предыдущими модулями.

Лестница внутри модуля: `увидел → понял → изменил → дополнил → написал → исправил → применил`.

## Плотность (`interactions`)

| Класс модуля | Интерактивов |
|---|---|
| простая | 4–6 |
| важная | 6–10 |
| сложная | 10–15, разбитых на части |

Пропорция по всей программе: **70% код и интерактив, 20% квиз и разбор, 10% чистая теория.**
Теория появляется прямо перед местом, где она нужна.

## Поля модуля

```json
{
  "id": "py-cond-if",
  "title": "Условие if",
  "class": "важная",
  "concepts": ["if", "отступ", "истина и ложь"],
  "practice": ["read", "modify", "fill", "write", "fix", "quiz"],
  "interactions": 8,
  "skills": ["py-branching"],
  "prerequisites": ["py-compare"]
}
```

## Нижний слой: темы и миссии

Тема — не одна миссия. На сложную тему приходится 3–6 миссий, чтобы человек закрепил
её, а не прошёл один тест и пошёл дальше. Типовой набор миссий на тему: сюжетное
введение, исследование проблемы, код, production-случай.

```json
{
  "id": "pyo3-numpy",
  "title": "Передача NumPy array без копирования",
  "missions": 4
}
```

Темы достраиваются профессия за профессией. Пока у модуля тем нет, плотность практики
задаёт поле `interactions`; как только появляется `topics`, проверка считает миссии.
Оба состояния валидны одновременно — граф наполняется постепенно, а не одним рывком.

## Rust не общий фундамент

Rust входит в разные профессии по-разному, со своим сюжетом и своей причиной:

| Профессия | Зачем Rust |
|---|---|
| Data Scientist | performance-слой: горячий участок, PyO3, Arrow/Polars, inference |
| ML Engineer | глубже: serving, конкурентность, производительность |
| Data Engineer | пайплайны, Arrow, потоковая обработка |
| AI Engineer | inference, токенизаторы, runtime |
| Python-разработчик | факультативно |
| Frontend, аналитик | не нужен |

Технически `ownership`, `Vec` и прочая база переиспользуются как общие курсы, но
профессиональная причина и практика у каждой профессии своя.
